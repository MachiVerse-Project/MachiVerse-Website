MACHIVERSE / ARCHITECTURE & DESIGN

世界をつなぐために、
境界をはっきり分ける。

MachiVerseは、世界を状態の集合ではなく、因果と歴史を持つ動的なシステムとして扱います。 そのために、世界状態の正本、外部接続、利用者向け表示、運用管理の責務を分け、Protocolで接続する構成を採っています。

01 / DESIGN PRINCIPLES

世界の「今」だけでなく、
「なぜ今こうなのか」を扱う。

MachiVerseの中心にあるのは、表面的な機能数を増やすことではなく、世界の要素同士を因果でつなぐ考え方です。 都市、住民、自然環境、社会関係を固定された完成物として置くのではなく、過去の状態と選択の積み重ねから現在が形成され、現在の変化が未来へ残る世界を志向します。

CAUSALITY & HISTORY

現在には履歴がある

世界状態を時点ごとの見た目だけでなく、過去から続く変化の結果として扱います。

DETERMINISM

再現可能性を契約にする

同じWorld Seed、同じsimulation-affecting Config、同じ有効Operation集合・順序・適用Stepから、同じ論理的な世界結果を得ることを基本契約にします。

SEPARATION

責務を分離する

Core、Gateway、General View、Admin Viewを独立した実行・ビルド・配布単位として扱います。

PROTOCOL FIRST

境界はProtocolにする

内部型や共通DTO DLLを通信契約として共有せず、versioned Protocol / schemaをコンポーネント間の境界にします。

02 / TOP-LEVEL COMPONENTS

4つに分ける。
でも、世界はひとつ。

コード、build、配布、実行単位まで独立させ、他コンポーネント内部への直接method callを行わず、Protocolだけを通じて連携します。

Simulation Core正本WorldState / Simulation Step / Operation / Persistence
GatewayAuth / Cache / Mediation / Publication / Resync
General ViewDiver / Spectator / Browser UI / Prediction
Admin ViewHealth / Log / Metrics / Config / Operations
正本はCore。Gateway cacheやView表示状態は派生状態です。

General ViewとAdmin ViewはCoreへ直接接続しません。Gatewayが外部接続・認証認可・cache・Operation集約・publication・再同期などを担い、Coreの責務を外側へ漏らさない構成です。

03 / HIGH-LEVEL SPECIFICATION

まず押さえるべき、
全体仕様。

以下は現行の全体アーキテクチャで定義されている標準構成の要点です。個別Protocolや各シミュレーション領域の詳細は、本体リポジトリの設計書が正本です。

項目標準設計意味
世界状態の正本Simulation CoreのみGateway cache、View表示状態、予測状態は非権威な派生状態。
標準トポロジSimulation Core 1 / Gateway 1:NGeneral View / Admin ViewはGateway経由で接続。標準ProtocolにCore↔Core通信はない。
権威ある時間整数ベースのSimulation Step社会的な暦・時計とは別概念。標準計算頻度は30Hzで外部Configから変更可能。
決定論同じ再現条件から同じ論理結果処理速度、OS scheduling、thread完了順、Gateway数、network到着競争などをworld outcomeへ持ち込まない。
通信境界Versioned Protocol / schemaMajor不一致は接続拒否。同一Major内の新Minorは後方互換を維持する設計。
Config各componentが自身の外部Configを所有simulation-affecting Configとdisplay / ops-only Configを区別し、安全な明示境界で適用する。
View prediction非権威・presentation-onlyDiver操作ではlocal prediction / correctionを許容しても、最終的にはCore確定状態へreconcileする。

04 / AUTHORITATIVE OPERATION FLOW

操作は予測できる。
確定するのはCore。

General View側では、利用者にリアルタイムに感じられるようlocal prediction / correctionを許容します。ただし予測状態は正本ではなく、Gatewayを経由してSimulation Coreで確定した状態へreconcileします。

General View
   ↓
Gateway
   ↓ auth / authorization / mediation
Simulation Core
   ↓ authoritative apply
confirmed WorldState
   ↓
Gateway → View reconciliation

BOUNDARIES

  • 未認可OperationをCoreへ送らない
  • Operation IDはretryやreconnectを跨いで維持
  • 同じOperationを世界へ二重適用しない
  • Coreが最終的な有効適用Stepを確定
  • Viewのpredictionは正本ではない
