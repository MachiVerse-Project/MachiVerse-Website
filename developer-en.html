SYSTEM DEVELOPMENT

01 / ARCHITECTURE

Split the responsibilities.
Keep one connected world.

MachiVerse treats four top-level components as independent execution, build, and distribution units. Communication boundaries use versioned Protocol / schema rather than sharing internal types or implementation DLLs as contracts.

Simulation CoreWorldState / Operation / Persistence
GatewayAuth / Cache / Publication
General ViewBrowser / Participation / Prediction
Administration ViewHealth / Config / Operations
In Alpha 1.0, all four are actually connected.
COREReal startup, mutation, and recovery verified.
GATEWAYReal Core / View / Admin connections established.
GENERAL VIEWBrowser E2E and the foundation for prediction / reconciliation are connected.
ADMIN VIEWHealth and Config read / change E2E flows are established.

START-ALPHA.BAT

What the script does

01Checks the .NET SDK.
02Release-builds all four components.
03Starts and synchronizes Core / Gateway.
04Starts both Views and opens them in the browser.

03 / ENGINEERING PRINCIPLES

Before writing code,
protect the contracts.

To grow a world simulator over time, reproducibility and clear boundaries take priority over implementation convenience.

DETERMINISMThe same World Seed, config, and operations should converge to the same result.
PROTOCOLUse versioned Protocol / schema as the communication boundary instead of internal types or shared DTO libraries.
DESIGN FIRSTRead the relevant design docs and AGENTS.md; do not turn unapproved assumptions into implementation facts.
CONFIGTunable values should remain changeable through external Config owned by each component.

04 / CURRENT LIMITATIONS

Alpha 1.0 is
not the finished system.

“Connected” and “production-ready” are different claims.

The current local Alpha profile is loopback-only for development and integration and is not a substitute for a production security profile.
